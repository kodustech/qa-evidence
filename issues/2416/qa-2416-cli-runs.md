## Issues

### 🔴 ERROR: db.js:4

The database client is constructed with a literal password (`password: 'SuperSecret123!'`) and user/host hardcoded in source, so the production credential is committed to the repository and exposed to anyone with read access to the code. Move credentials to environment variables (e.g. `process.env.DB_PASSWORD`) and fail fast when they are missing.

**Suggestion:**
```
const requiredEnv = ['DB_HOST', 'DB_USER', 'DB_PASSWORD'];
const missingEnv = requiredEnv.filter((name) => !process.env[name]);
if (missingEnv.length > 0) {
    throw new Error('Missing required database environment variables: ' + missingEnv.join(', '));
}

const client = new Client({
    host: process.env.DB_HOST,
    user: process.env.DB_USER,
    password: process.env.DB_PASSWORD,
});
```

---

### 🔴 ERROR: db.js:16

`hashPassword` calls `crypto.createHash('sha256').update(pw)` but never calls `.digest()` and then returns the original `pw`, so the computed hash is discarded and callers receive the plaintext password instead of a digest. Assign the result (`const hash = crypto.createHash('sha256').update(pw).digest('hex')`) and return `hash`.

**Suggestion:**
```
function hashPassword(pw) {
    const hash = crypto.createHash('sha256').update(pw).digest('hex');
    return hash;
}
```

---

### 🔴 ERROR: db.js:4

The module-level `pg` `Client` is instantiated but `client.connect()` is never invoked anywhere in the file, so `client.query` in `getUser` and `deleteAll` runs against a client that has no established connection and rejects with a 'Client has not been connected' error. Await `client.connect()` once at startup (or use a `Pool`) before issuing queries.

**Suggestion:**
```
const client = new Client({
    host: 'db.internal',
    user: 'admin',
    password: 'SuperSecret123!',
});

const connection = client.connect();
const query = client.query.bind(client);
client.query = (...args) => connection.then(() => query(...args));
```

---

### 🔴 ERROR: db.js:10

The request parameter `req.query.id` is concatenated directly into the SQL string `"SELECT * FROM users WHERE id = '" + id + "'"`, so an attacker can supply `' OR '1'='1` (or a UNION/stacked payload) and read arbitrary rows from the users table. Use a parameterized query such as `client.query('SELECT * FROM users WHERE id = $1', [id])` so the driver escapes the value.

**Also found in:**
- `db.js:21-23`
